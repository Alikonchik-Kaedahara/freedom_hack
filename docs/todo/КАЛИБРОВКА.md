Зачем: организаторы отбирают прежде всего по совпадению оценок системы с их экспертными по каждому критерию
на 10 контрольных чатах. Их эталона у нас нет — делаем свой маленький и подгоняем правила чек-листа, а не код.

## Шаг 1. Выбрать 12 чатов из DEV (10 мин, все)

По четыре на язык. Обязательно включить:

- `p1-ru-009`, `p1-kz-015`, `p1-en-014` — данные о счёте сообщены без идентификации (наше решение: 03 «Нет» и 08 «Да»);
- `p1-ru-025` — клиент ушёл, не сформулировав запрос (ожидаем N/A по 02, 04, 07);

## Шаг 4. Что делать с расхождениями

1. Модель ошибается системно (например, засчитывает прощание без итога как «Да» по 07) → правка формулировки правила
   в конструкторе чек-листа → новая версия → «Применить» → переоценка. Код не трогаем.
2. Модель права, мы нет → исправить консенсус (так тоже бывает).
3. Расхождение неустранимо текстом правила → оставить, упомянуть в README в «Ограничениях».

После правок переоценить 12 чатов и пересчитать сводку. Итоговый процент по cloud — в README.
