# ТЗ для Алихана: интерфейс как готовый продукт отдела качества

Написано 8 ноября, 01:40. Исполнитель — Алихан (фронтенд), приёмка — Томирис. Код фронтенда с этого момента
правит только Алихан; Томирис и Ерлан фронт не трогают, чтобы не было конфликтов.

## Кто пользуется и зачем

Пользователь — супервайзер контакт-центра Freedom Broker или аналитик отдела качества. Открывает систему
каждый день, чтобы: увидеть, какие диалоги требуют разбора; разобрать диалог с оператором; решить апелляцию;
посмотреть, кто из операторов систематически нарушает правила; при необходимости поправить чек-лист.

Три правила, по которым принимается каждый экран:

1. **Ни слова о том, как система устроена.** Пользователь не знает и не должен знать слова «модель», «движок»,
   «replay», «токены», «промпт», «валидатор», «group_id», «API», «Xrm», «snapshot». Такие слова допустимы только
   на вкладке «Настройки → Модель». Везде остальное — «оценка», «проверка», «система».
2. **Каждая кнопка называется тем, что произойдёт.** «Оценить 12 диалогов», «Подать апелляцию», «Сохранить
   чек-лист», «Скачать отчёт». Не «Применить», «OK», «Разбор →».
3. **Состояние видно без догадок.** У каждого экрана есть три состояния: загрузка (скелет), пусто (что сделать,
   кнопка), ошибка (что случилось и что сделать). Ничего не крутится и не мигает само по себе.

## 1. Визуальный стиль (P0)

Один акцент — зелёный Freedom. Всё остальное нейтральное. Никаких «терминалов», свечений и теней.

| Токен | Значение | Где |
|---|---|---|
| `--cqa-brand-primary` | `#009951` | единственный акцент: главная кнопка экрана, активная вкладка, ссылки |
| `--cqa-brand-hover` | `#007F43` | наведение |
| `--cqa-bg-canvas` | `#F3F5F4` | фон страницы |
| `--cqa-bg-surface` | `#FFFFFF` | карточки, таблицы, шапка страницы |
| `--cqa-border-hairline` | `#DDE3E0` | все границы, 1px; теней нет вообще |
| `--cqa-text-primary` | `#111816` | основной текст |
| `--cqa-text-secondary` | `#4C5B54` | подписи |
| `--cqa-text-muted` | `#7B8A82` | вторичные пояснения |
| статусы | pass `#047857 / #ECFDF5`, warn `#B45309 / #FFFBEB`, fail `#B91C1C / #FEF2F2` | только для вердиктов и баллов |

Шрифт: один — `Inter` (fallback Segoe UI, system-ui). Размеры: текст 13.5px, подписи 12px, заголовок карточки 15px/600,
заголовок страницы 20px/700. **Моноширинный шрифт остаётся только у ID диалогов и таймкодов.** Все числа — обычным
шрифтом с `font-variant-numeric: tabular-nums`. Капслока нет нигде: заголовки таблиц, секций, попапов — обычным
регистром.

Плотность: строка таблицы 40px, отступ карточки 14px 16px, радиус 6px у карточек и 4px у кнопок и полей,
расстояние между карточками 12px. Графики — без градиентов и анимаций появления.

Кнопки: на экране ровно одна зелёная (главное действие), остальные — белые с границей; третьестепенные — текстовые.
Иконка в кнопке только если она помогает узнать действие (скачать, добавить); «✓» и «→» в текстах кнопок не ставить.

Тёмная тема остаётся как есть (переключатель в шапке), но все правила выше действуют и в ней.

## 2. Шапка и навигация (P0)

Рамка Dynamics 365 (верхняя тёмная панель «Dynamics 365 | Freedom Broker — Омниканальный контроль качества»
и левая колонка разделов) **по умолчанию выключена**. Она включается автоматически только внутри настоящего
Dynamics 365 (когда есть `Xrm`) и вручную тумблером «Настройки → Интеграция». Для жюри это один клик, чтобы
показать встраивание; для пользователя — самостоятельное приложение.

Шапка приложения, 52px, тёмно-зелёная (`#0B3324`), одна строка:

```
┌──────────────────────────────────────────────────────────────────────────────────────────────┐
│ [F] Freedom Broker · Контроль качества   Главная  Диалоги  Операторы  Апелляции(1)  Качество оценки  Настройки   │ Набор: DEV · 65 ▾ │ ☾ │ ТА Томирис · супервайзер │
```

- Слева: логотип, «Freedom Broker», тонкая вертикальная линия, «Контроль качества» (это название продукта, одно
  на все экраны; «Conversation Quality Analytics» и «CQA TERMINAL» убрать).
- Шесть разделов вместо восьми: **Главная · Диалоги · Операторы · Апелляции · Качество оценки · Настройки**.
  «Чек-листы» и «Справочник» переезжают во вкладки настроек (раздел 9) — это конфигурация, а не ежедневная работа.
- Справа: выбор набора (как сейчас, но «Набор: DEV · 65» без моноширинного шрифта), переключатель темы,

  просто очищает имя). Имя и роль задаются в «Настройки → Пользователь» (раздел 9) и используются в апелляциях.
- Главное действие экрана (например «Оценить 12 диалогов») живёт в шапке страницы, а не в шапке приложения:
  `rb-action` убрать.

Телефон: нижняя панель из пяти вкладок — Главная, Диалоги, Апелляции, Операторы, Ещё (внутри: Качество оценки,

Файлы: `web/js/app.js` (NAV, buildShell, renderChrome, setHostPreview по умолчанию `false`), `tools/app.src.css`
(`.ribbon`, `.rb-*`, `.cqa-d365-*`, `.tabbar`).

## 6. Апелляции (P0)

- У апелляции и решения появляются автор и время: «Подал: Томирис А., 8 ноя 01:12», «Решил: Алихан Е., 8 ноя 01:40».
  Автор берётся из «Настройки → Пользователь»; если имя не задано, при первой апелляции система просит его ввести.
  Бэкенд уже готов: `POST /api/results/<key>/appeals` принимает поле `author`, решение — поле `by`; оба
  возвращаются в объекте апелляции (`appeal.author`, `appeal.decision.by`) и печатаются в отчёте. Фронт их передаёт
  и показывает.
- Список: столбцы «Критерий · Диалог · Оператор · Подал · Когда · Статус», клик по строке открывает модал решения.
- Модал решения: слева цитата из апелляции и доказательства, справа вердикт «Оставить» / «Изменить на …» с живым
  пересчётом (есть), обязательное поле «Основание решения», кнопка «Принять решение».
- Пустое состояние: «Апелляций нет. Их подают из карточки диалога, кнопкой «Подать апелляцию» у критерия».

Файлы: `web/js/views/appeals.js`, `server.py` (create_appeal, decide — поля `author`, `by`).

## Словарь интерфейса

Одно понятие — одно слово на всех экранах.

| Пишем | Не пишем |
|---|---|
| оценка | скоринг, результат модели, вердикт модели |
| система оценила / автоматическая оценка | модель, LLM, AI, ИИ |
| проверяющий | ревьюер, супервайзер (как роль — можно) |
| оператор | агент |
| грубая ошибка | критический флаг, флаг 08, критично |
| спорная оценка | needsReview, низкая уверенность (как причина — можно) |
| второе мнение | повторная оценка, переоценка (это другое действие) |
| набор диалогов | датасет, группа, group_id |
| чек-лист, критерий, правило | скрипт, сценарий |
| апелляция, решение, основание | тикет, ревью |

## Как сдавать

Ветка `ui-product` от свежего `main`, по одному коммиту на раздел (1–9), пуш после каждого, чтобы Томирис принимала
по частям. Стили — только в `tools/app.src.css` с пересборкой `python tools/prefix_css.py tools/app.src.css web/css/app.css`.
Скриншоты до/после — в комментарий к пушу в чат команды.
